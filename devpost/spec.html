One flow. Two different kinds of questions.

1 · Taste test

Understand work genres

10–12 real, source-grounded direction questions. Many internships share work genres; this is not a card or test for every opportunity.

Reviewed question set → direction. Not a skills exam and not claimed verbatim employer interview questions.

2 · Scout-like questions

Set your preferences

Topics, locations, Research/Company, funding, remote preference, visa needs, keywords and organizations.

Taste-test suggestions stay editable. They never choose targets for the student.

3 · Live discovery

Filter and choose

TinyFish searches and reads sources. Ranked, evidence-backed results with filters, save/hide and explicit target selection.

No fixed program list. The student chooses the internships to plan for.

4 · Readiness + timetable

Check preparation

Academic eligibility, the short readiness interview, manual exam weeks and free hours—for the student's choices.

This later interview checks preparation. The first taste test checks direction.

5 · Overview

One action this week

Research/Company cards plus one actionable next step across selected targets. No invented task when there is nothing actionable.

The agreed two-level roadmap remains unchanged.

6 · Track timeline

Shared work, real deadlines

Shared preparation appears once, before its earliest deadline. Program-specific steps retain tags and evidence.

One capacity budget across both tracks. Closed, at-risk and unscheduled work are explicit.

What talks to what

AI and code have different jobs

  • TinyFish: discover and read the web.
  • AI: extract quoted facts and assess answers against rubrics.
  • Code: validate outputs, calculate explainable fit, evaluate supported criteria and allocate preparation.
  • The student: choose targets and change preferences/timetable.
Official evidence is not automatic certainty. Missing or ambiguous conditions remain unconfirmed. A quote validates provenance, not every interpretation. Never invent a deadline, funding guarantee or interview stage.
Finite versus live: the genre-question bank is curated; the internship search pool is live. The named programs in our research are verification examples, not the whole product.

05 · Shared tasks, deadline scheduler and two roadmap levels

External services, exact calls and honest costs

TinyFish

GET api.search.tinyfish.ai
Query/preferences → title/snippet/URL leads.

POST api.fetch.tinyfish.ai
Up to 10 URLs/request → text/links + per-URL errors.

POST agent.tinyfish.ai/v1/automation/run-async
Authorized fallback → run ID; poll/cancel using /v1/runs/:id.

All use server-side X-API-Key. The full payload/response contracts are in the canonical spec.

Groq — learner-owned API access

The learner explicitly chose Groq during build. Use GROQ_API_KEY only on the server. Proposed Groq-hosted openai/gpt-oss-120b with strict structured outputs; no Replit-managed OpenAI inference.

  • Separate extraction, question-pack and assessment schemas.
  • Validate evidence and IDs; correct JSON does not prove truth.
  • Usage follows the learner's Groq account. No claim of free or unlimited calls.
  • Enforce conservative shared caps and respect request/token limits.
  • Documented endpoint
  • Account limits
  • Strict structured outputs
Search/Fetch and Groq smoke-tested: Real calls passed with secured keys, and a live app search returned a CERN opportunity. Failures and timeout can leave partial results. TinyFish's allowance/wallet descriptions conflict, so no free/unlimited claim is made. Paid Agent fallback stays disabled until separately authorized with verified enforcement; no wallet top-ups.
Freshness is not guaranteed by a parameter. Current Fetch docs say ttl:0 can still return cache-valid content. Keep retrieved/interpreted timestamps and cache labels; elapsed-deadline checks are separate from live page verification.
